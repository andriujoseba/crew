- `kimi` sessions now record their token usage on `SESSION END`. Kimi reports
  no usage on stdout, so the profile reads it from the session's own
  `wire.jsonl` artifact after the CLI exits, summing `token_usage` across the
  session's steps. `input_other` is recorded as the contract's uncached
  `input_tokens` and the two cache counters as themselves; no cost is
  reported, because kimi publishes none.
- A `kimi` session's id is now pinned by the engine rather than minted by the
  CLI, which is what makes that artifact addressable. A session whose id could
  not be pinned records its usage as absent rather than approximating it from
  the filesystem.

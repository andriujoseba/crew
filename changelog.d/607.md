### Changed

- A `reviewer` box is minted at the builder's size — 4 CPU, 8GiB, 60GiB — because
  a review re-runs the builder's whole suite, then a mutation probe over a
  corrupted copy, then lint sweeps the builder never runs (#607).
- `reviewer.conf` no longer calls the role lean or its worktrees throwaway: the
  comment above the figures names what the role actually runs, so the reasoning
  that produced the wrong size cannot restore it (#607).
- `triage` sizing is unchanged — its stated premise is accurate and nothing
  measured contradicts it (#607).
- A box cloned from a gold snapshot — `crew new --from`, or a roster line with a
  fourth column — is sized at the role's cpu and memory instead of silently
  inheriting the snapshot's (#607).
- That capability is probed on `box new --help` rather than compared by version,
  and the probe fails closed: a host whose box cannot size a copy clones exactly
  as it did before (#607).
- Every clone now ends in one line saying what landed, per figure — cpu, memory
  and disk each `applied`, `NOT applied` or `unverified`, beside the size the box
  carries and the size the role profile asks for (#607).
- The carried size is read back off the daemon rather than inferred, and the line
  names the resize route for whatever did not land, so a partial landing is said
  out loud instead of passing as a success (#607).
- `--disk` is never passed on a clone: box serves it there only from a source
  with a root device of its own and refuses before anything is created, so
  asking would trade the mint itself for a clearer number (#607, box#171).

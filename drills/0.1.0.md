## What was skipped, and why

**Three per role — `pre-auth: login WARN`, `no .boot-id marker`, `no sessions
spawned`.** These assert creds-free behaviour, and all three boxes were already
`gh`-authenticated from prior runs. The harness never touches credentials, so
proving these needs a box that has never been logged in. They are skipped
by design on a re-run, not silently passed.

**They are also a coverage gap in `0.1.0`'s evidence.** Both readings hold at
once: the harness did the right thing, and the run still produced less evidence
than a fresh box set would have. Nine skips across the three roles — the
creds-free half of phase 1 went unexercised on this hardware, so `0.1.0` ships
with no drill evidence for those three assertions on a box that had never been
logged in.

**What covers it is #207 §1 and §3** — installing the published artifact on a
machine that is not the drill host, and a second operator building a crew from
scratch on the written docs. Both exercise the creds-free path on hardware with
no drill history at all, which is stronger evidence than a drill box minted to
be never-authenticated: such a box proves the minting, not the path. On that
ground [#116's ruling A](https://github.com/heavy-duty/crew/issues/116#issuecomment-5158719146)
struck the criterion that would have re-drilled this and named the gap here
instead (#306).

**One in the app phase — the floor-vs-CLI agreement comparison for
`crew-drill-triage`:**

```
skip agree: crew-drill-triage — crew status shows it up;
            floor says offline because: SILENT — no tick for 10m
ok   the agreement check ran (2 of 3 boxes yielded a floor-vs-CLI comparison)
```

The two readers genuinely disagreed about that one box: `crew status` calls it
up because its cron line is live, and the floor calls it SILENT because
`SILENT_AFTER_S` is two tick intervals and its last tick was ten minutes old.
Section A leaves `crew-drill-triage` armed but does not tick it, so during a
long run it can cross the threshold while still being, by the CLI's definition,
a working box.

The check **passed** — the vacuity floor added by #50 requires at least one
real comparison, and two of three yielded one. Recorded here because a skip
inside a passing check is exactly the shape that has hidden this assertion's
failures four times before (#50, #181), and because it is a real disagreement
between two readers rather than a harness artifact. Worth a `0.1.1` issue; it
does not gate this release.

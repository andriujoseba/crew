## Findings

Five findings were handed to #327 for the `0.1.3` window. None falsifies an
acceptance criterion of #400, so none holds this release:

1. `gh_identity` logs its failed-auth WARN to stdout inside a command
   substitution, so the WARN is captured as the box's identity and the tick
   reports a git-identity mismatch instead of dead `gh` authentication.
   Confirmed independently on reviewer and triage; all three roles failed the
   assertion.
2. Failure and completion instructions hardcode stale `crew PR #16`, sending
   drill reports to the wrong pull request.
3. One role assertion failure prevents `DRILLED`/`CONFIG_BOX` from being
   populated and silently suppresses Section A, config, and app. Removing one
   unrelated red between passes 2 and 3 recovered **56 assertions** across
   those phases.
4. `bot_session_terminal` exists only in `kimi.conf`. The engine treats the
   hook as optional while the drill requires it, leaving the breaker leg
   blocked on an operator ruling.
5. The builder and attention fixtures are not fully removed. Pass 2 left a
   claimed builder issue and branch; pass 3's resume lane correctly recovered
   them, opened PR #9, and occupied the build slot before the builder leg.

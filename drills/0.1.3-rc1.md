# Release drill — 0.1.3-rc1 — 2026-09-07

**No real-host drill round has been run for this candidate, and this record is
not a waiver.** That distinction is the first line because
[`drills/0.1.1.md`](0.1.1.md) — the only other record in this directory without
a round — *is* a waiver, and reading this one as another would invert what the
rc ladder is for. `0.1.1` decided not to drill. This candidate is cut **in
order to be drilled**: the round it is owed is **Gate A of
[heavy-duty/crew#659](https://github.com/heavy-duty/crew/issues/659)**, it is
named with its exact invocation below, and its readings land in this file
before the promotion to `0.1.3`.

`drills/README.md` states what the gate wants: *"The guard requires a **record**,
not a passing result"*. What it demands before this merge is therefore this
file, not the round — and the round runs after the merge, against the published
`0.1.3-rc1` tag, with its readings appended here before the promotion.

That is triage's ruling of `2026-09-07` on crew#659, and **this PR carries the
correction to `drills/README.md` that it turns on**: the *"what it does not
buy"* paragraph conflated the record with the round, inferring from the true
premise *"the first rc round still drills a mutable candidate"* that the round
had to precede the merge. It no longer does, and it names the three grounds —
the candidate is what the fleet can install, the tag pins the SHA a branch
cannot, and the append is unobstructed because `drill-recorded` asserts nothing
on the `0.1.3-rc2-dev` tree the merge door re-arms `main` to. Its pointer to
crew#490 was spent as well; that issue closed `2026-08-26`.

**The one non-stamp path is the cut's own breakage, and it is named here rather
than left to be found.** `reset-up-marks-every-roster-box` spelled
`CHECKPOINT_STALE=0.1.3-dev` on both sides of its expectation. The mark carries
the engine version — `cmd_up` passes `$ENGINE_VERSION` to
`checkpoint_stale_gate`, and `resolve_engine` sets that from this tree's
`VERSION` — so moving `VERSION` moved the value out from under a literal, and
the suite went red at the cut. The expectation now reads `VERSION`. Re-spelling
the literal would have fixed nothing for longer than one commit: the release
merge door re-arms `main` as `0.1.3-rc2-dev` automatically, in the same job as
the publish. `stamps-only.py` is vacuous on an rc tree and so does not object;
the path matters at the **promotion**, where the diff from this candidate's tag
to the final must touch stamps only — and this change is *inside* the tag, below
that anchor, so it is not in that diff.

## The round this file is waiting for

Gate A of crew#659, quoted as that issue carries it:

> `drill/rehearsal-all.sh --app-roster <path>` run on @danmt's drill host, where
> `<path>` names a roster carrying at least one **live armed member** — not a
> drill box — and the round's agreement block names at least one qualifying
> member with its measured delta and uncertainty, and the round's box census is
> unchanged by the second named-roster pass.

⚠️ **The invocation is quoted above as #494 wrote it, and it must be read under
crew#659's `2026-09-07` amendment: the round is run with `--ref 0.1.3-rc1`.**
The quoted criterion is deliberately not re-worded — a relocated criterion that
drifts is one nobody agreed to — but taken bare it is now wrong in a way that
would not announce itself. `drill/rehearsal-all.sh:57` reads
`INSTALL_REF="${CREW_DRILL_REF:-main}"`, and the merge door re-arms `main` as
`0.1.3-rc2-dev` the instant this cut lands, so a round with no `--ref`, taken
when this gate is read, drills a tree that is **not this candidate** — and it
would say so only in the summary's `## drilled source: <sha> (remote … ref
main)` line, which nothing on the gate asks anybody to read. **The round this
file is waiting for is therefore:**

    drill/rehearsal-all.sh --ref 0.1.3-rc1 --app-roster <path>

A tag resolves through the same phase-0 path a branch does and lands on the
record as the resolved SHA, which is what crew#490 was built for.

Two further things about that invocation are recorded here because they decide
whether a round counts:

- **`--app-roster` is not optional.** The armed pass runs inside
  `[ "$APP" -eq 1 ] && [ -n "$APP_ROSTER" ]`, and the generated drill-roles pass
  can never qualify in its place: `rehearsal.sh` disarms cron on every box a
  round mints, while `agreement_armed_skewed()` requires `disarmed = False` and
  `tick_fresh = True`. The roster file is expected as a `*.roster.local` beside
  the drill.
- **The verdict is written either way.** `agreement_round_result()` returns
  `could-not-compare` on a zero armed count, so a round cannot print a false
  green — but crew#659 A2 requires the verdict, `compared` or
  `could-not-compare`, to be **read at this gate and written into this file**.
  A `could-not-compare` does not block promotion; it discharges the question
  rather than deferring it to a seventh round.

**Where a defect found by that round goes.** Not into a hand-edit of this file's
claims about the tree: crew#659 states that *"a defect found after the cut is a
re-cut, never a hand-edit"*, and `changelog-assembled` replays the merge base,
so the fix lands on `main` and ships as `0.1.3-rc2` with its own record at
`drills/0.1.3-rc2.md`. What is appended to *this* file is the round's readings —
`drills/` is a stamp path, so that append is admitted by `stamps-only.py` rather
than being the kind of edit it refuses.
